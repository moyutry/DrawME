# 🎨 צייר ונחש - חדר פרטי אחד

משחק ציור וניחוש מלא בעברית, בהשראת Scribble/skribbl.io. האתר בנוי כ-**PWA** (אפשר "להתקין" אותו כמו אפליקציה), כולל שרת realtime (Socket.IO) ולקוח פשוט ב-HTML/CSS/JS רגיל בלי שום שלב build.

## איך זה עובד (חשוב להבין)

בניגוד ל-Scribble המקורי, **אין כאן רשימת חדרים** ואין קודי הזמנה. כפתור "שחקו עכשיו" מכניס את כולם **לאותו חדר יחיד** באתר:

- **מי שנכנס ראשון לחדר ריק (אין אף אחד אחר) הופך אוטומטית למנהל/ת** ומקבל שליטה על הגדרות המשחק.
- כשהמנהל/ת עוזב/ת, התפקיד עובר אוטומטית לשחקן/ית הבא/ה שנשאר/ה בחדר.
- **הגדרות החדר (מספר סבבים, זמן ציור, מילים מותאמות אישית וכו') נשמרות תמיד** - גם כשכל השחקנים עוזבים ומתחברים מחדש, וגם אחרי שהשרת עצמו מופעל מחדש (ר' סעיף מסד הנתונים למטה).
- כשהחדר מתרוקן לגמרי, כל משחק פעיל מתאפס אוטומטית (חוזר ללובי), אבל ההגדרות נשארות בדיוק כפי שהוגדרו.

## פיצ'רים

- כניסה עם שם וצבע בלבד - אין הרשמה
- לובי עם רשימת שחקנים, כתר למנהל/ת, ופאנל הגדרות
- **הגדרות מלאות** (רק למנהל/ת, ניתנות לשינוי בלובי): מספר סבבים, זמן ציור, כמות מילים לבחירה, מספר רמזים, מקסימום שחקנים, מילים מותאמות אישית, ומצב "רק מילים מותאמות אישית"
- זרימת משחק מלאה: בחירת מילה (עם טיימר), ציור, ניחוש בצ'אט, רמזים שנחשפים בהדרגה, ניקוד לפי מהירות (גם למנחש/ת וגם לצייר/ת), חשיפת מילה, ולוח תוצאות סופי
- לוח ציור מלא: פלטת צבעים, עובי מברשת, מחק (eraser), דלי צבע (fill), בטל (undo), נקה הכל - ותומך גם במגע (טאצ') וגם בעכבר
- צ'אט חי + ניחושים "קרוב!" + תגובות אימוג'י מרחפות
- מנהל/ת יכול/ה להסיר שחקן/ית מהחדר
- **PWA**: אפשר להתקין כאפליקציה במחשב ובנייד (עם אייקונים אמיתיים), ועובד גם עם קאש בסיסי אופליין למסך הפתיחה
- כל הממשק בעברית ו-RTL, ובנק מילים בעברית (200+ מילים, אפשר להוסיף עוד דרך "מילים מותאמות אישית")

## מבנה הפרויקט

```
server/         קוד השרת (Node.js + Express + Socket.IO)
  index.js      נקודת הכניסה, חיווט אירועי socket
  room.js       כל לוגיקת המשחק (חדר יחיד, תורות, ניקוד, הגדרות)
  words.js      בנק המילים בעברית
  db.js         שמירת הגדרות (MongoDB או קובץ מקומי)
public/         קוד הלקוח (סטטי, בלי build)
  index.html, css/style.css, js/app.js, js/canvas.js
  manifest.json, service-worker.js, icons/
scripts/generate-icons.js   סקריפט שיצר את אייקוני ה-PWA
```

## הרצה מקומית

דורש [Node.js](https://nodejs.org) גרסה 18 ומעלה.

```bash
npm install
npm start
```

האתר יעלה בכתובת http://localhost:3000 - פתחו אותו בשני טאבים/דפדפנים כדי לדמות שני שחקנים.

לפיתוח עם הפעלה מחדש אוטומטית בכל שינוי קובץ:

```bash
npm run dev
```

בלי הגדרת מסד נתונים, ההגדרות יישמרו בקובץ `server/data/settings.json` (מספיק לבדיקה מקומית).

## שמירת הגדרות לצמיתות (MongoDB Atlas - חינמי)

כדי שההגדרות באמת ישרדו גם דיפלוי מחדש של השרת באחסון חינמי (ולא רק הפעלה מחדש רגילה), מומלץ לחבר מסד נתונים חינמי:

1. הירשמו בחינם ל-[MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register)
2. צרו Cluster חינמי מסוג **M0** (Free tier)
3. תחת **Database Access** - צרו משתמש עם שם וסיסמה
4. תחת **Network Access** - הוסיפו כלל `0.0.0.0/0` (Allow access from anywhere) כדי שהשרת בענן יוכל להתחבר
5. לחצו **Connect → Drivers**, העתיקו את מחרוזת ההתחברות (נראית כך: `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/`)
6. הכניסו את הסיסמה שלכם במקום `<password>` במחרוזת

בהרצה מקומית: העתיקו את `.env.example` לקובץ בשם `.env` והדביקו את המחרוזת לתוך `MONGODB_URI`.
בפריסה בענן (למטה): מגדירים את `MONGODB_URI` כמשתנה סביבה (Environment Variable) בממשק האחסון.

אם לא תגדירו MongoDB בכלל - הכל עדיין יעבוד, רק שההגדרות יישמרו רק בקובץ מקומי על השרת (בחלק מהאחסונים החינמיים הקובץ הזה יימחק בדיפלוי הבא).

## פריסה חינמית לאינטרנט

המשחק צריך שרת עם חיבור מתמשך (Socket.IO/WebSocket), אז **לא** מתאים לאחסון סטטי כמו GitHub Pages. הכי מתאים: **Render.com** (יש חינם אמיתי בלי כרטיס אשראי).

### אפשרות מומלצת: Render

1. העלו את הפרויקט ל-GitHub (ריפו חדש):
   ```bash
   git init
   git add .
   git commit -m "משחק צייר ונחש"
   git branch -M main
   git remote add origin <כתובת הריפו שלכם ב-GitHub>
   git push -u origin main
   ```
2. היכנסו ל-[render.com](https://render.com) והתחברו עם GitHub
3. **New +** → **Web Service** → בחרו את הריפו שיצרתם
4. הגדרות:
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
5. תחת **Environment** הוסיפו משתנה `MONGODB_URI` עם מחרוזת ההתחברות מ-Atlas (מומלץ, ר' למעלה)
6. לחצו **Create Web Service** - אחרי כמה דקות תקבלו כתובת ציבורית כמו `https://your-app.onrender.com`

**הערה חשובה על התוכנית החינמית של Render**: השרת "נרדם" אחרי כ-15 דקות בלי תנועה, וההתעוררות הראשונה לוקחת כ-30-50 שניות. זה נורמלי לגמרי לשימוש קליל עם חברים - פשוט תנו לדף להיטען.

### אפשרויות חינמיות נוספות

- **[Railway](https://railway.app)** - נוח מאוד, יש קרדיט חינמי חודשי (לא ללא הגבלה)
- **[Fly.io](https://fly.io)** - תוכנית חינמית נדיבה, דורש התקנת CLI (`flyctl`)
- **[Glitch](https://glitch.com)** - הכי פשוט להתחיל בלי Git בכלל, אבל פחות יציב לפרויקט קבוע

בכל האפשרויות האלה תהליך העבודה דומה: לחברו לריפו/להעלות קוד, `npm install` כ-build ו-`npm start` כהרצה, ולהגדיר `MONGODB_URI` כמשתנה סביבה אם רוצים שההגדרות ישרדו לצמיתות.

## הוספת מילים / שינוי מילים

בנק המילים המובנה נמצא ב-[server/words.js](server/words.js) - אפשר לערוך אותו ישירות. אפשרות נוספת (בלי לגעת בקוד): המנהל/ת יכול/ה להוסיף "מילים מותאמות אישית" ישירות מהלובי באתר.

## מגבלות ידועות

- **בלי זיהוי שחקן/ית קבוע**: אם מרעננים את הדף (F5) נכנסים כשחקן/ית חדש/ה בלי הניקוד הקודם - זה תואם לבקשה "פשוט וקל" ולרוב מספיק למשחק מזדמן עם חברים.
- מצב המשחק הפעיל (מי מצייר עכשיו, הציור על הלוח) **לא** נשמר בין הפעלות שרת - רק **הגדרות** החדר נשמרות. זה בסדר גמור כי משחק פעיל ממילא לא אמור לשרוד קריסת שרת.
- כמות מקסימלית סבירה לחדר יחיד היא סביב 15-20 שחקנים בו-זמנית; לא נבנה לעומסים גדולים יותר.
